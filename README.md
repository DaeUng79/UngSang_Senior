## 매년 기록물이 결정되면

1. **자료 확정:** 작품마다 이름·제목·과거/현재 사진·두 사진의 장소/촬영 시기/설명을 모으고 관리번호를 부여합니다.
2. **원본 보존:** 새 연도 전용 폴더에 원본과 확정 문구를 저장합니다. 이전 연도 전시를 남기는 방식을 기본안으로 합니다.
3. **웹용 사진 준비:** 별도 작업본에서 편집 문자를 제거하고 두 시점의 사진 크기·배치를 정합니다. 모바일용 WebP도 만듭니다.
4. **글과 사진 연결:** 원문 JSON, 화면 발췌 문구 JSON, 영상·크기 목록을 같은 작품 번호로 맞춥니다.
5. **전시 생성:** 새 연도 전용 작업 사본에서 전시를 만들고 `site/archive/연도/`로 옮깁니다.
6. **확인·공개:** 담당자가 모바일 사진·문구를 확인한 뒤 ‘전시 이야기’를 새 전시에 연결하고 배포합니다.
7. **연도 마감:** 공개 파일, 확정 데이터, 원본, 최종 프레임, 제작 기록, 배포 버전을 함께 보존합니다.

구체적인 파일 형식과 명령은 **[연간 갱신 절차](docs/annual-update.md)**에 있습니다. 현재 스크립트에는 2026년 경로가 고정되어 있습니다. 연도 선택 기능은 아직 없으며 첫 후속 연도 전시를 추가할 때 연도 간 링크도 반영합니다.

## 폴더 구조

```text
README.md                 운영 안내의 시작점
docs/                     관리 절차·대장·인수인계 양식
records/2026/             2026년 공개 기준 데이터 사본 3종
site/                     GitHub Pages 실제 공개 파일
  index.html              첫 화면
  app.js / style.css      첫 화면 문구·재생·배치
  assets/                 사진·글꼴·로고
  archive/                2026년 전시와 다운로드 영상
scripts/                  제작 스크립트·전시 화면 원본
.github/workflows/        site/ 배포 설정
doc/                      원본 PDF·사진·기존 HWP (로컬 보존)
output/                   최종 프레임·제작 데이터·납품본 (로컬 보존)
tmp/                      판독 이미지·비교 화면·로그 (정리 대상)
```

`docs/`는 운영 문서, `doc/`는 원자료입니다. `site/` 밖의 파일은 Pages 배포 대상이 아니지만, **공개 GitHub 저장소에 커밋한 파일 자체는 공개**됩니다. 원본·업무 문서는 별도 보관합니다.

## 어느 파일을 고치나요?

| 바꿀 내용 | 수정 원본 | 반영 방법 |
|---|---|---|
| 첫 화면 문구·순서·시간 | `site/app.js`의 `scenes` | 직접 수정 |
| 첫 화면 사진별 글 위치 | `scenes`의 `copyPosition`, `site/style.css` | `bottom-left` 또는 `top-right` 지정 |
| 첫 화면 소개글·참여자·문의처·전시 링크 | `site/index.html` | 직접 수정 |
| 첫 화면 사진 | `site/assets/photos/` | 640px·1080px WebP 교체 |
| 전시 이름·제목·전후 장소·날짜·설명 | `output/video/archive-content.json` | 전시 생성 |
| 사진 위 발췌 글·위치 | `scripts/motion_overlays.json` | 전시 생성 |
| 전시 머리말·로고·문의처·하단 | `scripts/archive_gallery.html`, `scripts/archive.css` | 전시 생성 |
| 움직이는 사진 효과 | `scripts/motion-sample.css`, `scripts/motion-sample.js` | 전시 생성 |
| 전시 명조 웹폰트·새 글자 추가 | `scripts/prepare_archive_font.py`, `site/assets/fonts/archive-serif.json` | 글꼴 준비 후 전시 생성 |
| 작품 순서·영상 파일·화면 크기 | `output/video/pages-02-12/manifest.json` | 전시 생성 |

`site/archive/index.html`은 생성 결과입니다. 이 파일만 고치면 다음 생성 때 수정이 사라집니다. `pages-02-12`는 초기 작업 때 정한 이름이며 현재는 **1~12페이지 모두** 들어 있습니다.

`records/2026/`는 공개 기준 사본으로 현재 생성기가 직접 읽는 경로는 아닙니다. 정식 수정 때 작업 데이터와 기준 사본을 함께 갱신합니다.

## 미리보기·배포

프로젝트 루트에서 실행합니다. 완성된 사이트 미리보기에는 Python 외의 패키지가 필요하지 않습니다.

```sh
python3 -m http.server 8765 --directory site
```

브라우저에서 `http://localhost:8765/`와 `http://localhost:8765/archive/`를 엽니다.

2026년 작업 데이터와 공개용 사진·영상이 있는 환경에서 전시를 다시 생성하려면:

```sh
python3 scripts/build_public_archive.py
```

이 명령은 **완성된 사진·영상과 확정 글을 묶는 작업**입니다. PDF 추출·영상 생성은 하지 않습니다. GitHub 사본에는 `output/`이 없으므로 [작업 데이터 복원 절차](docs/annual-update.md#2026년-글이나-배치만-수정할-때)를 먼저 수행합니다.

`main`에 반영하면 `.github/workflows/pages.yml`이 `site/`를 배포합니다. 로컬 작업 폴더에 `.git`이 없다면 별도의 Git 체크아웃에 수정 파일을 옮겨 커밋·푸시해야 합니다. `/private/tmp/` 배포 사본은 영구 보관 장소로 사용하지 않습니다.

## 운영 시 기억할 사항

- 첫 화면 사진 11장과 전시 작품 12건은 다른 구성입니다. 같은 번호를 동일 작품으로 가정하지 않습니다.
- 전시는 두 WebP 사진과 HTML 글을 과거→현재 5초, 현재→과거 5초로 왕복 전환합니다. 다운로드 MP4는 각 5초입니다.
- 첫 화면은 Noto Sans KR·Nanum Brush Script, 전시 제목·서정 문구·작품 설명은 Noto Serif KR 기반 웹폰트를 사용합니다. 웹폰트는 현재 쓰는 글자만 포함합니다. 새 글자가 추가되면 원본 글꼴로 다시 준비합니다. 전시 생성기는 명조 웹폰트의 글자 누락을 확인해, 누락 시 재생성을 안내하고 중단합니다. 안내·버튼용 고딕은 시스템 글꼴입니다.
- 일부 사진 가장자리는 AI 편집을 거쳤습니다. 원본·편집본·생성 기록을 구분하고 확인되지 않은 과거 건물·사물을 만들어 기록으로 취급하지 않습니다.
- 사업계획·예산·성과·동의 여부는 웹사이트 파일만으로 확정할 수 없습니다. 기본 문서 대장에서 확인 상태를 따로 관리합니다.
